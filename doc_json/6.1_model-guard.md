# Model Guard

Model Guard is a content safety and guardrails service in the Agentic AI Platform. It helps you analyze text and images for harmful content, detect jailbreak and prompt injection attempts, and enforce configurable safety thresholds before content reaches your AI models.

## Content Safety Analysis[​](#content-safety-analysis "Direct link to Content Safety Analysis")

Model Guard provides comprehensive safety analysis powered by Google's Gemini LLM:

* **Harm Categories** — Analyzes content for hate, violence, sexual content, self-harm, and harassment
* **Multimodal Analysis** — Evaluates images alongside text for visual safety violations
* **Jailbreak Detection** — Identifies attempts to bypass AI safety guidelines
* **Prompt Injection Detection** — Catches hidden instructions and manipulation attempts, including image-based jailbreaks
* **Configurable Thresholds** — Adjust sensitivity for dangerous and violent categories to match your use case

## Intelligent Processing[​](#intelligent-processing "Direct link to Intelligent Processing")

The service is designed for efficiency:

* **Single API Call** — All safety checks are performed in one operation
* **Parallel Image Processing** — Multiple images are downloaded and processed concurrently
* **Large Content Support** — Handles large content seamlessly
* **Low Latency** — Optimized for sub-500ms response times in most cases

## Multimodal Support[​](#multimodal-support "Direct link to Multimodal Support")

Model Guard supports both text and image analysis:

* **Base64 Data URIs** — Embed images directly in requests
* **HTTPS URLs** — External images are automatically downloaded
* **Multiple Formats** — JPEG, PNG, GIF, and WEBP
* **Graceful Error Handling** — Failed images do not block text analysis; processing continues with successfully loaded images

### Image Analysis Features[​](#image-analysis-features "Direct link to Image Analysis Features")

When analyzing images, the service checks for:

* Explicit or sexual content
* Violence, gore, or graphic imagery
* Hate symbols or discriminatory visual content
* Visual jailbreak attempts (e.g., screenshots of malicious prompts)
* Hidden text or instructions in images

## Configuration Options[​](#configuration-options "Direct link to Configuration Options")

### Risk Threshold[​](#risk-threshold "Direct link to Risk Threshold")

You can configure the risk threshold for dangerous and violent categories:

* **Range** — 0.0 to 1.0 (maximum 0.8, system enforced)
* **Lower values** — More sensitive (flags more content)
* **Higher values** — Less sensitive (only flags high-risk content)
* **Scope** — Applies only to dangerous and violent categories; other categories use server-side thresholds
* **Jailbreak and Prompt Injection** — Always enabled with fixed system thresholds

### Severity Levels[​](#severity-levels "Direct link to Severity Levels")

Content is classified by severity based on risk score:

| Severity | Risk Score   | Behavior                                    |
| -------- | ------------ | ------------------------------------------- |
| Low      | < 0.4        | Logged but allowed by default               |
| Medium   | 0.4 to < 0.6 | Logged, may require review                  |
| High     | 0.6 to < 0.8 | Logged, marked unsafe, review recommended   |
| Critical | ≥ 0.8        | Logged, marked unsafe, blocking recommended |

### Recommendations[​](#recommendations "Direct link to Recommendations")

The service returns an action recommendation based on the overall risk score:

* **Allow** — When risk is below the review threshold
* **Review** — When risk is elevated but below the block threshold
* **Block** — When risk exceeds the block threshold

## Response Structure[​](#response-structure "Direct link to Response Structure")

Analysis results include:

* **Safe** — Boolean indicating whether content is safe to use
* **Overall Risk Score** — Maximum risk across all detected categories (0.0–1.0)
* **Recommendation** — Suggested action (allow, review, block)
* **Category Scores** — Risk scores per harm category
* **Flagged Categories** — Categories that exceeded their thresholds
* **Explanation** — Human-readable safety assessment
* **Confidence Score** — Confidence in the analysis (0.0–1.0)

When images are analyzed, responses also include token usage metrics (prompt tokens, output tokens, total tokens).

## Metadata Tracking[​](#metadata-tracking "Direct link to Metadata Tracking")

You can include optional metadata for audit, analytics, and correlation:

* **Actor Information** — Actor ID and type (user, agent, service, system)
* **Session and Request** — Request ID, session ID
* **Agent Orchestration** — Agent ID, thread ID, run ID, step name, graph step ID
* **Knowledge Base** — Library ID, document ID
* **Source** — Request source system or application

Metadata is optional, returned in responses, stored with violations for audit trails, and privacy-safe (no sensitive content stored).

## Violations Retrieval[​](#violations-retrieval "Direct link to Violations Retrieval")

When content exceeds the violation threshold, records are stored for audit and investigation. You can:

* **List Violations** — Paginated retrieval with filters
* **Filter by Metadata** — Actor, session, agent, source, risk score, recommendation
* **Sort Results** — By risk score, timestamp, processing time
* **Query Syntax** — FIQL (Feed Item Query Language) for complex filters

Stored violation records include metadata, risk scores, flagged categories, and recommendations. Image data is not stored—only text content and metadata about images.

## Security Considerations[​](#security-considerations "Direct link to Security Considerations")

* **Content Privacy** — Analyzed content is stored with violation records only when risk exceeds the violation threshold
* **Configurable Thresholds** — Server administrators can adjust when violations are stored, when review is recommended, and when blocking is recommended
* **Encryption** — Data in transit and at rest is encrypted
* **Authentication** — TID token-based authentication with audience validation
* **Rate Limiting** — Protects against abuse and ensures fair usage
* **Audit Logging** — All requests are logged for security and compliance

## Rate Limits[​](#rate-limits "Direct link to Rate Limits")

The service enforces rate limits to ensure fair usage:

* **Per-user limits** — Requests per minute
* **Concurrency** — Burst limit for concurrent requests
* **Content size** — Maximum payload size per request

## Error Handling[​](#error-handling "Direct link to Error Handling")

The service returns structured error responses for common scenarios:

* Invalid request format or parameters
* Missing or invalid authentication
* Insufficient permissions
* Payload size exceeded
* Rate limit exceeded
* Server or service availability issues

All error responses include detailed information for troubleshooting.

## Getting Started[​](#getting-started "Direct link to Getting Started")

To use Model Guard:

1. **Authentication** — Obtain a valid TID access token with the required scopes (`openid`, `models`, `profile`)
2. **Terms of Service** — Agree to the platform terms before use
3. **Integration** — Integrate content analysis into your workflow before sending content to AI models

For detailed API documentation and integration examples, refer to the Model Guard API specification and interactive docs available in the service.
